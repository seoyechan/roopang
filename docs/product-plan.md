# 월급루팡 서비스 기획안

작성일: 2026-09-30 · 디자인 검토용 초안 · 보상/수집함 확장 반영

## 1. 서비스 한 줄 소개

출근해서 잠깐 쉬는 시간을 돈으로 보여주는, 로그인 없는 유쾌한 월급 타이머.

**시급을 입력하고 ‘루팡 시작’을 누르면 금액이 올라간다. 다시 일할 때 ‘일 시작’을 누르면 기록이 저장된다.**

## 2. 이번 버전에 담을 것

| 기능 | 동작 |
| --- | --- |
| 시급 입력 | 원 단위 양수를 입력. 한 번 입력하면 같은 브라우저에서 다음 방문에도 유지 |
| 루팡 시작 | 이번 회차 금액과 경과 시간 측정 시작 |
| 실시간 금액 | 시급 ÷ 3,600 × 실제 경과 초로 계산, 1초마다 표시 갱신 |
| 일 시작 | 측정 종료 및 날짜별 기록에 반영. 버튼은 다시 ‘루팡 시작’으로 변경 |
| 날짜별 기록 | 해당 날짜에 누적한 금액과 쉬었던 시간 표시 |
| 월별 합계 | 선택한 달의 누적 금액과 누적 시간. 이전·다음 달 이동 |
| 오늘의 보상 | 오늘 5,000원 커피 → 10,000원 짜장면 → 20,000원 치킨 → 50,000원 외식 |
| 누적 목표 | 전체 기록 합계로 5천 원부터 100만 원, 이후 자동차까지 단계별 달성 |
| 루팡 수집함 | 지금까지 모은 커피·짜장면 등의 그림과 개수, 누적 목표 컬렉션 표시 |
| 보상 애니메이션 | 목표 달성 시 해당 물건이 위에서 떨어져 수집함으로 들어가는 효과 |
| 자동 저장 | 시급, 종료한 회차, 진행 중 회차를 브라우저에 저장 |

금액은 입력한 시급에 따른 재미용 환산값이다. 세금이나 실제 급여 지급액을 계산하지 않는다.

## 3. 디자인 방향

**콘셉트: 잠깐 쉬어도, 월급은 흐르니까.**

- 밝은 아이보리 배경, 진한 검정 글자, 초록색 한 가지 강조색.
- 가장 중요한 것은 커지는 숫자와 시작·종료 버튼. 기록은 그 아래 배치.
- 검은 안대와 초록 넥타이를 착용한 작은 괴도 캐릭터를 브랜드 요소로 사용.
- 굵은 한국어 산세리프 제목과 폭이 일정한 숫자. 금액이 변해도 화면이 흔들리지 않게 한다.
- 모서리는 16~20px 범위로 통일하고 얇은 테두리로 영역을 구분.
- 화면 전체에 움직임을 넣지 않고 숫자, 캐릭터, 목표 달성 순간에 집중.
- 디자인 기준: 레이아웃 변화 6/10, 움직임 6/10, 정보 밀도 3/10. 자체 디자인이며 특정 공식 디자인 시스템을 사용한 것은 아님.

### PC

상단 브랜드와 ‘내 기록’ 링크 → 제목과 캐릭터 → 큰 금액/타이머와 시급/버튼을 나란히 배치 → 오늘의 보상과 다음 누적 목표 → 그림으로 보여주는 수집함 → 월별 합계와 날짜별 기록.

### 모바일

브랜드 → 짧은 제목과 작은 캐릭터 → 금액 → 경과 시간 → 오늘의 다음 보상 한 줄 → 시급 → 가로 전체 버튼 → 수집함 → 다음 누적 목표 → 월별 기록 순서로 한 열 배치. 누적 전체 단계는 ‘전체 목표’에서 펼쳐 본다.

- 360px부터 가로 스크롤 없이 동작. 320px에서도 핵심 조작이 잘리지 않도록 대응.
- 모바일 입력 시 숫자 키패드 사용. 버튼 높이는 최소 48px.
- 금액이 커지면 글자 크기를 줄이고 통화 단위를 분리하여 넘침 방지.
- PC 최대 본문 폭 약 1,120px. 모바일에서 캐릭터 크기와 상단 여백을 줄여 버튼을 쉽게 찾게 한다.

## 4. 화면 상태와 버튼

| 상태 | 금액·안내 | 주요 버튼 |
| --- | --- | --- |
| 첫 방문 | 0원, ‘시급을 알려주세요’ | 루팡 시작. 누를 때 시급 유효성 확인 |
| 시급 입력 완료 | ‘1초에 약 4.17원’처럼 환산 속도 안내 | 루팡 시작 |
| 루팡 진행 | 이번 회차 금액, 경과 시간, ‘루팡 중’ 표시 | 일 시작 |
| 종료 | ‘이번 루팡 1,250원 · 5분’ 결과를 다음 시작 전까지 유지 | 루팡 시작 |
| 기록 없음 | ‘아직 기록이 없어요. 첫 루팡을 시작해 보세요.’ | 기존 시작 버튼 사용 |
| 저장 불가 | ‘기록을 저장할 수 없어요. 이 창을 닫으면 사라질 수 있어요.’ | 현재 창에서 계속 사용 가능 |

- 종료 후 다시 시작하면 이번 회차 금액은 0부터 시작한다. 오늘·월별 합계는 유지한다.
- 측정 중에는 시급 수정을 잠근다. 종료 후 수정한 시급은 다음 회차부터 적용한다.
- 빈 값, 0, 음수, 숫자 이외의 입력은 허용하지 않는다. 허용 범위는 1~10,000,000원으로 제안한다.
- 시급은 최초에 비워 둔다. 시안의 15,000원은 예시이며 사용자에게 자동 적용하지 않는다.

## 5. 재미와 애니메이션

### 숫자 카운터

- 큰 원 단위 숫자는 1초마다 변경되는 자리만 180~240ms 동안 위로 넘어간다.
- 소수점 두 자리는 작고 옅게 표시하여 낮은 시급에서도 변화가 보이게 한다.
- 숫자 정렬과 컨테이너 폭은 고정한다. 매초 전체 숫자를 확대하거나 깜빡이지 않는다.
- 경과 시간은 `시:분:초`로 표시한다.

### 캐릭터

- 대기 중: 돈통 옆에서 기다리는 모습.
- 루팡 중: 느리게 들썩이는 쉬는 동작. 코인 효과는 작고 드물게.
- 종료: 짧게 자세를 바꾸고 멈춘다.

### 오늘의 보상 + 누적 목표 + 루팡 수집함

사용자 요청을 반영해 커피 단일 목표를 단계별 보상으로 확장한다. **오늘은 커피와 짜장면을 모으고, 전체 누적으로는 자동차를 향한다.** 세부 규칙과 연출은 [보상·수집함 상세 기획](reward-collection-plan.md)을 기준으로 한다.

- 커피 기준은 기존 4,000원에서 **5,000원**으로 변경.
- 오늘의 보상: 커피 5,000원, 짜장면 10,000원, 치킨 20,000원, 외식 50,000원. 각 보상은 하루 한 번씩 획득.
- 전체 누적 목표: 5,000원부터 커피·짜장면·치킨·외식·쇼핑·운동화·헤드폰·여행 순서로 100만 원까지 이어진다. 이후 노트북·드림카 준비·자동차까지 확장.
- 누적 목표는 전체 기간에 단계별 한 번만 해금. 일일 수집 개수에 추가로 더하지 않는다.
- 오늘 금액은 자정에 새로 시작하지만, 이미 모은 수집 개수와 전체 누적 목표는 유지.
- 달성한 보상 그림이 내려와 한 번 튕긴 뒤 수집함에 들어간다. ‘커피 12잔’처럼 이미지와 개수가 함께 표시된다.
- 시각 효과와 저장을 분리한다. 새로고침·다중 탭·백그라운드 복귀로 보상이 중복 지급되지 않도록 한다.
- 금액은 차감하지 않는다. 실제 상품을 지급하거나 구매하는 서비스가 아니며, 기록에 붙는 재미용 기념 보상이다.
- 소리는 기본 제공하지 않는다. `prefers-reduced-motion`에서는 낙하·튕김 없이 달성 문구와 개수만 갱신한다.

루팡 영수증, 공유, 랭킹은 이번 버전 범위에서 제외한다.

## 6. 기록과 계산 규칙

### 계산

`회차 금액 = 회차 시작 시 확정된 시급 × (현재 시각 - 시작 시각) / 3,600,000`

- 예시: 시급 15,000원 × 300초 ÷ 3,600 = 1,250원.
- 타이머가 실행된 횟수를 더하지 않는다. 시작 시각과 현재 시각의 차이로 계산한다.
- 내부 계산은 반올림하지 않고, 화면에 표시할 때만 회차 소수점 두 자리·목록 정수 단위로 표시한다.
- 월 합계는 반올림한 일별 표시값의 합이 아닌 원본 금액의 합에서 계산한다. 표시 단위 차이로 최대 몇 원 차이가 생길 수 있으므로 필요 시 상세에서 소수 금액 제공.
- 진행 중 금액도 오늘·월·전체 합계 및 보상 판정에 즉시 포함한다. 종료 시 중복 합산하지 않는다.

### 날짜 경계

- 1차 버전은 한국 서비스 기준 `Asia/Seoul`의 날짜로 집계한다.
- 자정을 넘기는 회차는 각 날짜의 경계에서 시간을 나누어 저장·집계한다. 월말에도 동일하게 처리한다.
- 목록은 날짜 내림차순. 월을 바꾸면 해당 월 합계와 기록만 표시한다.

### 백그라운드와 재방문

- 다른 탭으로 이동하거나 휴대폰 화면이 꺼져도 사용자가 ‘일 시작’을 누를 때까지 측정은 이어진다.
- 탭이나 브라우저를 닫았다가 돌아와도 진행 회차의 시작 시각으로 복구한다. 재방문 시 ‘진행 중인 루팡을 이어서 표시했어요’ 안내.
- 8시간을 초과해 진행 중인 회차에는 ‘아직 쉬는 중인가요?’ 안내와 종료 버튼을 제공한다. 임의로 종료하지 않는다.
- 잘못 켜 둔 회차는 해당 날짜 상세에서 회차 단위 삭제 가능. 삭제 전 확인하고 합계와 목표 상태를 재계산한다.
- 사용자 시스템 시계 변경이 계산에 영향을 줄 수 있다. 음수 경과는 0으로 제한하고 시간 변경을 감지하면 확인 안내를 표시한다.

## 7. 저장 설계

로그인·서버 없이 `localStorage`에 저장한다. 저장 키는 `roopang:v1`.

```ts
type StoredData = {
  version: 1;
  hourlyWage: number | null;
  activeSession: {
    id: string;
    hourlyWage: number;
    startedAt: number;
  } | null;
  sessions: {
    id: string;
    hourlyWage: number;
    startedAt: number;
    endedAt: number;
  }[];
  rewardCatalogVersion: 1;
  // daily:2026-09-30:coffee, lifetime:sneakers 같은 고유 키.
  // 획득 내역/개수는 회차에서 계산하고 아래 값은 축하 재생 여부만 관리.
  celebratedRewardKeys: string[];
};
```

- 시급 변경, 시작, 종료, 삭제, 목표 달성 시 저장. 매초 저장하지 않는다.
- 합계는 회차에서 계산한다. 합계와 회차를 따로 수정하다가 값이 달라지는 문제를 피한다.
- 수집 개수는 해당 일일 목표를 달성한 날짜 수로 계산한다. 누적 목표는 전체 금액으로 해금한다. 회차 삭제 시 함께 재계산한다.
- JSON 읽기 실패나 잘못된 데이터 형식을 감지하면 안내하고 원본을 자동 삭제하지 않는다.
- 저장 실패를 화면에 표시한다. 단순히 ‘저장 완료’로 처리하지 않는다.
- 같은 사이트의 여러 탭에서는 저장 변경을 반영하고, 중복 시작·종료로 같은 회차가 겹쳐 저장되지 않도록 조정한다.
- 다른 기기·브라우저에는 동기화되지 않는다. 브라우저 데이터 삭제나 시크릿 모드 종료 시 기록이 사라질 수 있다.
- 화면 안내: ‘시급과 기록은 이 브라우저에 저장돼요.’

## 8. 구현 제안

- React + TypeScript + Vite 기반 반응형 단일 페이지.
- 스타일은 CSS 변수로 색상·여백·반경을 통일. 짧은 CSS 전환으로 숫자/캐릭터 움직임 구현.
- 첫 버전에는 서버, 로그인, 데이터베이스가 필요하지 않다.
- 한국어 폰트는 자체 호스팅하고 대체 폰트를 지정. 숫자에는 tabular numerals 적용.
- 입력 라벨, 키보드 조작, 명확한 포커스, 4.5:1 이상의 텍스트 대비 확보.
- 매초 갱신되는 숫자를 스크린 리더가 계속 읽지 않게 하고 시작·종료·달성만 알린다.

## 9. 구현 완료 확인 기준

1. 시급 15,000원에서 5분 경과 시 금액 1,250원이 된다.
2. 시작·종료를 반복해도 회차가 중복되지 않고 일·월 합계가 맞는다.
3. 새로고침 후 시급·이전 기록·진행 회차를 복구한다.
4. 백그라운드 복귀 시 실제 경과 시간과 맞는다.
5. 자정·월말을 넘긴 금액을 두 날짜·두 달에 정확히 나눈다.
6. 시급 변경은 과거 기록에 영향을 주지 않는다.
7. 오늘 5,000원에서 커피, 10,000원에서 짜장면을 각각 한 번 획득한다. 자정 후에도 수집함 개수는 유지한다.
8. 360px·390px·768px·1440px에서 입력·숫자·버튼이 잘리지 않는다.
9. 기록 없음·입력 오류·저장 실패·동작 줄이기 설정에 대응한다.
10. 여러 탭에서 동시에 조작해도 진행 회차와 합계가 일치한다.
11. 전체 누적 목표는 100만 원과 자동차까지 다음 단계로 바뀌며 일일 보상 개수에 중복 가산하지 않는다.
12. 여러 목표를 한 번에 넘거나 회차를 삭제해도 수집 개수·달성 상태·재생 여부가 규칙과 일치한다.

- 보상·수집함 세부 기획: [reward-collection-plan.md](reward-collection-plan.md)
- 시안의 금액과 기록은 예시 데이터. 실제 서비스 첫 방문은 0원과 빈 기록으로 시작한다.
- 현재 단계는 디자인과 기획이다. 기능 구현과 실제 반응형·애니메이션 검증은 이후 진행한다.
- 사용자 지정값: 커피 5,000원, 짜장면 10,000원. 제안값: 나머지 품목과 목표 금액, 일일 각 1회 수집, 자동차 3천만 원, 한국 시간 집계, 8시간 경과 안내.
- 다음 단계: 시안 피드백 반영 → 반응형 구현 → 계산·저장·날짜 경계 검증 → 배포.
